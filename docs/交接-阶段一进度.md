## ⚠️ 待验证：任务 1 的功能验证（这是继续开发的前提）

### macOS 上验证失败的两个原因（均非方案本身问题）

1. **网页抢快捷键**：在 GitLab 页面测试时，`Cmd+Shift+L` 被网页自己捕获（弹出 GitLab 搜索框），
   没传到扩展
2. **macOS 授权缺失**：从终端跑 `osascript` 报 `-1743 未获得授权将Apple事件发送给Google Chrome`，
   `keystroke` 压根没发出去

**已确认的事实**：快捷键注册本身正常——Chrome `Preferences` 里有
`mac:Command+Shift+L -> toggle_sidepanel`（扩展 `enbddkjkifhhlpcgojekpkdndponnodk`），
但该项 `global: false`，意味着**只在 Chrome 焦点内生效、且会被网页优先捕获**。

### Windows 上要做的验证

前提：该机 Chrome 已加载 AIChat 插件。

**方式一（推荐，接近真实场景）**：
```
npm run tauri dev
```
起应用 → 切到「机器状态」页 → 点「打开插件侧边栏」按钮 → 看侧边栏是否打开。

**方式二（快速验证底层命令）**：cmd 里跑
```cmd
powershell -Command "Add-Type -AssemblyName Microsoft.VisualBasic; Add-Type -AssemblyName System.Windows.Forms; $p = Get-Process -Name chrome -ErrorAction SilentlyContinue | Where-Object { $_.MainWindowHandle -ne 0 } | Select-Object -First 1; if ($p) { [Microsoft.VisualBasic.Interaction]::AppActivate($p.Id); Start-Sleep -Milliseconds 400; [System.Windows.Forms.SendKeys]::SendWait('^+l'); Write-Host 'sent' } else { Write-Host 'chrome not found' }"
```

**必须分两种情况各测一次**：

| # | Chrome 当前停在 | 关注点 |
|---|---|---|
| 1 | 空白页 / 新标签页 | 侧边栏能否打开（验证基本可行性） |
| 2 | **1688 页面** | 侧边栏能否打开（验证会不会被业务页面抢走快捷键） |

**情况 2 是重点**。macOS 上已实测 GitLab 会抢走该快捷键；若 1688 页面也抢，方案需加
「先切到空白标签页再发按键」这一步，或改走 CDP。

### 验证结果决定下一步

- ✅ 两种情况都能开 → 任务 1 通过，继续任务 2（重启 Chrome）
- ⚠️ 仅空白页能开 → 需补「先切空白页」逻辑，再重测
- ❌ 都不能开 → 方案需换（考虑 CDP），并更新 `docs/客户端演进规划.md` 第 4 节
